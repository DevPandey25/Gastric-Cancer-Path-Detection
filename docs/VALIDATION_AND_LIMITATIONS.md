# GastricPath AI — Scientific Validation Scope & Research Limitations

This document defines the formal boundaries of validation, known technical constraints, data availability blockers, and scientific limitations of the GastricPath AI research software release.

---

## 1. Regulatory Status & Non-Clinical Use Notice

> [!WARNING]
> **NOT FOR PRIMARY CLINICAL DIAGNOSIS OR DIRECT PATIENT MANAGEMENT**
>
> GastricPath AI is an experimental research and investigative computational pathology platform developed for academic inquiry and methodology evaluation. It has **not** been submitted to, cleared by, or certified by any regulatory agency (including the US FDA, European CE-IVD / IVDR, or China NMPA).
>
> Output classifications, probabilities, attributions, and risk scores generated by this software must **never** be used as the sole basis for clinical decisions, surgical margins, oncological staging, or therapeutic interventions.

## 2. Patch-Level Categorization vs. Anatomical Diagnosis

### Standardized TUM Probability Wording
Throughout the software interface, API responses, and database records, the model's estimated tumor metric is strictly defined as:
> **`Predicted TUM class probability (patch-level model output)`**

### Scientific Distinction
- **What it is:** The mathematical probability assigned by a deep learning classifier that an individual, isolated $224 \times 224$ pixel tile belongs to the `TUM` (gastric adenocarcinoma) morphological class relative to 7 other non-neoplastic tissue classes.
- **What it is NOT:**
  - It is **not** a patient-level cancer diagnosis.
  - It is **not** an anatomical tumor area percentage (such as tumor surface area across a histological section).
  - It does **not** reflect tumor burden, surgical margin clearance, or clinical prognosis.

## 3. Data Availability Blockers & Architectural Invariants

| Research Domain | Module | Formal Status | Scientific Blocker Rationale |
|:---|:---:|:---:|:---|
| **Pixel-Level Tissue Segmentation** | Original Phase 6 | **Blocked by Data** | The GCHTID dataset contains strictly patch-level crops ($224 \times 224$) with discrete class labels. It contains **0 pixel-level masks, 0 polygon contour annotations, and 0 QuPath GeoJSON exports**. The 9-class U-Net software infrastructure is fully implemented, but supervised training is withheld to prevent scientific fabrication. |
| **Deep Learning Nuclei Segmentation** | Original Phase 7 | **Weight Blockage** | Pretrained weights for deep learning nuclear instance segmenters (Cellpose, StarDist, HoVer-Net) are absent from the offline local repository. To maintain strict offline reproducibility, the verified classical Ruifrok HED-watershed baseline was utilized. All segmented entities are designated as *candidate objects*, not verified nuclei. |
| **Whole-Slide Image (WSI) Repository** | Original Phase 9 | **Data Blockage** | GCHTID distributes isolated tiles without source whole-slide digital scans (`.svs`, `.ndpi`, `.mrxs`). The pure-Python WSI pyramid reader and Attention-MIL pipeline are validated on synthetic WSI arrays and coordinate patch grids, but zero clinical WSIs exist in the repository. |
| **Survival Outcome Analysis** | Original Phase 10 | **Provenance Blockage** | Clinical follow-up for overall survival (OS) in HMU-GC-Clinical was censored and unlinked from the GCHTID image tiles. Time-to-event Cox regression was withheld to prevent ungrounded survival claims. |
| **Clinical Cohort Invariant & Privacy** | Original Phase 10 | **Exploratory Cohort** | HMU-GC-Clinical contains $N=300$ complete patient records (0 dropped during cleaning). Individual patient admission IDs present in raw data are strictly withheld from application outputs. HER-2 categorization is exploratory ($24.67\%$ IHC 2+/3+ vs $75.33\%$ baseline). |
| **miRNA Target Interactions** | Original Phase 10 | **In-Silico Prediction** | Evaluated strictly for mature miRNA `hsa-miR-497-5p` across 3,711 interaction rows in `data/support/Gastric.xlsx`. Exactly 11 unique target genes achieve high consensus ($\ge 7/8$ algorithms). All scores represent computational bioinformatics predictions without wet-lab validation. |

## 4. Hardware & Environment Constraints

### CPU Execution & Absence of GPU Hardware
- The host system (Windows 11, AMD Ryzen 5 5500U, 16 GB RAM) does not possess dedicated NVIDIA CUDA-capable GPU hardware.
- PyTorch runs exclusively on CPU.
- Real-time CPU performance has been comprehensively benchmarked:
  - Model Load Latency: $53.85\ \text{ms}$
  - Single-Patch Preprocessing: $1.51 \pm 1.31\ \text{ms}$
  - Warm Inference Latency: $38.56\ \text{ms}$ ($25.94\ \text{patches/sec}$)
  - Peak Memory Usage (RSS): $237.63\ \text{MB}$
- GPU benchmarks are honestly documented as **not applicable** due to physical hardware absence.

### Docker Container Verification Status
- Production container definitions (`Dockerfile`, `docker-compose.yml`, `.dockerignore`) have been fully authored with non-root security boundaries and CPU-optimized dependencies.
- However, the Docker CLI and daemon are absent from the host system (`CommandNotFoundException`).
- Container builds and runtime health checks are formally classified as **"configuration authored, build/runtime verification unavailable"**. Native virtual environment execution is the primary verified target.

### Offline Sandbox Environment
- The platform operates within an isolated local sandbox with no outbound network access.
- All foundation model embeddings (Phikon, DINOv2) and experiment artifacts were pre-computed and cached locally.
- Zero live external API requests (e.g., to HuggingFace Hub, OpenAI, or cloud storage) are initiated during normal operation or test execution.

## 5. Methodological & Model Limitations

1. **Baseline Model Invariant:** The canonical `GastricCancerRNN` checkpoint (`models/checkpoints/gastric_rnn_classifier.pt`, SHA-256: `65369ef618ad1d0ad10ecb65b6f15324e932f52e21c8b25a43b71c636726d8b8`) has been strictly preserved without weight re-initialization or retraining. Its internal state records `val_accuracy: 0.6486` ($64.86\%$), the model registry records validation accuracy of $64.86\%$ and test accuracy of $56.82\%$, and historical Phase 3.2 evaluation on $N=3,110$ test patches achieved $65.92\%$ ($65.66\%$ strictly unexposed). An earlier draft text figure of $88.22\%$ is formally retracted.
2. **Foundation Model Subsetting & Provenance:** Due to memory and compute constraints in the offline CPU environment, comparative foundation model evaluation was conducted on the Phase 4.4 Reduced 10% Stratified Subset ($N=3,110$ total; $N=467$ held-out test partition). On this partition, Owkin Phikon Mean-Patch linear probing achieved **66.38% test accuracy, 0.9450 Macro OvR AUROC, and 66.54% Macro F1**. This protocol is formally distinguished from the separate Phase 4.2 full-dataset DINOv2 evaluation (65.08%, $N=4,665$). Furthermore, `dinov2_vits14` is the sole evaluated DINOv2 model; `dinov2_vitb14` was surveyed only.
3. **Spatial Graph Sample Size:** The spatial graph and GNN benchmark was conducted on an exploratory 64-patch pilot. While sufficient to prove that the Morphology MLP baseline ($23.75\%$ balanced accuracy) outperformed spatial GNNs ($21.25\%$), large-scale graph pretraining across thousands of slides remains future work.
